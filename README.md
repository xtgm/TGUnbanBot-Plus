基于 Cloudflare Workers 的 Telegram 群组自助解封机器人。机器人通过 Telegram Webhook 接收消息，帮助被封禁或被禁言的用户在私聊中完成自助解封流程，同时提供管理员黑名单、GKY 与本地 D1 双库查询、解封命令复制、群内举报投票、广告号自动检测、新机器人风控等能力。

## 与原项目的差异

| 改动点 | 说明 |
| --- | --- |
| **D1 唯一存储后端** | 黑名单 / 清扫缓存 / 批量任务 / 投票状态 / 指纹库全存 D1，免费层 10 万次/天写入不溢出，无 KV 依赖 |
| **黑名单结构升级** | `["123"]` → `[{id, reason, by, at}]`，记原因 / 操作人 / 时间；旧裸数组自动归一化，零迁移 |
| **多群组支持** | `GROUP_ID` 逗号分隔多群，解封与封禁遍历全部配置群；第一条为主群 |
| **全局黑名单处置闭环** | `/ban` `/spam` 加黑后**立即遍历全部群禁言**、`/sban` **立即遍历全部群踢出**（原项目只写库不踢人）；黑名单用户发言实时拦截删消息 + 踢人、复入群立即踢回 |
| **批量任务** | 四条命令（`/ban` `/sban` `/spam` `/unban`）支持多 TGID（半角 / 全角逗号 / 空格 / 换行 / `[123,456]`）；`U<20` 且 `U×G≤24` 且子请求 `≤100` 同步，否则转 D1 批量 + Queues 分片续接；单次最多 50 个 |
| **通知系统** | `OWNER_IDS[0]` 是主人（收全部通知），其余为副主人（收加黑踢出通知）；留空不发私聊通知 |
| **解封回执改造** | 不再给「返回某群」假链接（私有群点不动），改为**主群内联按钮** = 联系管理员入口；`SELF_UNBAN_CONTACT_GROUP` 可指定，拿不到链接自动降级不附按钮 |
| **D1 黑名单来源收紧** | **写入来源 = 真人执行的 `/ban` `/spam` `/sban` 等管理命令**；原生封禁按钮、第三方机器人封禁一律不写；黑名单永不自助解封，只能 `/unban` 移除 |
| **动态群组** | 第一主人私聊 `/addgroup` `/delgroup` `/listgroups` 增删群，存 D1 不改环境变量；三道硬校验，动态群永不顶替主群 |
| **`chat_member` 事件订阅** | 群内手动封禁**不再写黑名单**（仅审计通知）；手动解封时**封不回黑名单用户**（无法绕过全局黑名单） |
| **`/blacklist` 竖排排版** | 每条记录一段、字段各占一行，避免长字段撑爆折行；时间格式化、操作人译成可读角色并优先输出 `@username`（`tg://user` 链接会因对方隐私设置退化成死文本） |
| **`/check` 双库独立查询** | GKY 远程库与本地 D1 分别判断、各自给复制按钮，一边失败不吞另一边；GKY 记录属非配置群时只给「全局白名单」代码并提示影响范围 |
| **`/help` 第一主人专属** | 命令写成裸文本（Telegram 只对纯文本 `/xxx` 给「点击发送」），一条一行、权限写在分区标题 |
| **投票通过后昵称脱敏** | 脱敏为「首字***尾字」防止借投票卡片二次传播广告；进行中 / 被否决时显示完整昵称供成员判断 |
| **头像指纹 + 视觉识别** | 头像取自已有的 `getChat` 响应（零额外请求）：广告头像入库复用、`moondream` 识图读图内文字、定罪即学习、`/ignore` 同步纠错；单证只进观察，防止头像被盗用而连坐 |
| **正文图片指纹 + 视觉识别** | 图片 / 贴纸 / 动图 / 视频 / 文件消息以前**整条不进检测**（caption 空就被早退闸门丢掉）；现在按 `file_unique_id` 入库复用，同款图第二次出现零成本命中，首张由 `moondream` 识图判定，`AD_IMAGE_VISION_DAILY` 控制每日张数 |
| **同款会员标指纹** | 会员标取自已有的 `getChat` 响应（零额外请求）：广告组织统一配的标入库复用，同款标第二次出现即命中；**同款定罪 3 次起、且本次有其他佐证才参与定罪**，单证永不单独定罪（防常见标连坐），`/ignore` 同步纠错 |
| **重复举报预检** | 目标**已封禁且已入 D1** 时静默跳过（两条件须同时成立），不再刷注定通过的卡片 |
| **黑名单互动通知分两种** | 黑名单用户发 `/start` → 提示「尚未尝试解封」照常给介绍；发 `/unban` 或确认句 → 提示「正尝试申诉」并被闸门拒绝。闸门只守解封入口，不削弱 |

## 功能

### 普通用户

| 命令 | 使用位置 | 说明 |
| --- | --- | --- |
| `/start` | 私聊 | 收机器人介绍欢迎语（`START_WELCOME`，支持 HTML 子集） |
| `/unban` | 私聊 | **自助解封**：返回检查清单，用户粘贴 `SELF_UNBAN_KEYWORD` **完整整句**才触发。解封走全部配置群，成功回执含主群「联系管理员」按钮 |
| `/start check_用户ID` | 私聊深链 | 二次审核入口，机器人自动生成链接 |

### 群管理员

| 命令 | 使用位置 | 说明 |
| --- | --- | --- |
| `/ban 用户ID [原因]` | 私聊 / 群内 | 加入 D1 黑名单（`reason=manual`）+ 遍历全部群**永久禁言（不踢出）**（杀手 ON 群为踢出）。支持批量。群内撤回命令不发回执，详情私聊第一主人；**群内对单个 TGID 还会清扫当前群**（私聊与批量不做，大范围用 `/purge`） |
| `/sban 用户ID [原因]` | 群内（群主/第一主人/副主人）· 私聊（第一主人/副主人） | 加入 D1 黑名单 + 遍历全部群**踢出并撤回其历史发言**。`/ban` 改禁言后，要踢人就用这条；支持批量。**群里不留痕**：命令消息撤回、回执不发，完整逐群明细只走私聊主人 |
| `/spam [用户ID] [原因]` | 回复 / 私聊 / 直接输入 | 同上（`reason=spam`，**全群禁言**）+ **删除被回复的垃圾消息**；回复后文本作为原因 |
| `/unban 用户ID` | 私聊 / 群内 | 先删 D1 记录成功才解封；每群执行「恢复发言 + 解除封禁」两步（同一个人可能部分群被 `/sban` 踢、部分群被 `/ban` 禁言）；群内只发「目标 + 解封总数」汇总（目标可点击、TGID 可复制） |
| `/check TGID` | 回复 / 私聊 / 群内 | 查 GKY + 本地黑名单，输出**资料卡 + 时间线**（与 `/profile` 同渲染）。群内**不撤回**命令、结果留群里并私聊第一主人 |
| `/stats [范围]` | 群内 / 私聊 | 统计面板：活跃（消息 / 活跃人数）、增长（新增 / 离开 / 净增）、风控（处置 / 新人治理 / 被移出）。范围支持 `today` `week` `month` `昨天` `前天` `上周` `上月` `近7天` `近30天` `2026-09-10` `2026-09-01 2026-09-15`。数据页带时间切换与 7/30 天趋势（逐日 + 汇总 + 环比，**不出图**）。**广告不计入发言统计**，处置数按 +8 时区切天 |
| `/ad [原因]` | **仅群内回复** | 隐藏举报投票，赞成与反对**各 6 票**（`AD_VOTE_THRESHOLD`），任一配置群管理员点赞成或反对即一票定音；发起人自动算 1 票、可改投去重；命令发出即删 |

### 主人/副主人专属(`OWNER_IDS`)— 隐藏指令

| 命令 | 权限 | 说明 |
| --- | --- | --- |
| `/help` | 仅第一主人私聊 | 分区列出全部命令，一条一行，权限写在分区标题 |
| `/notice` | 仅第一主人私聊 | **全体通知**：发 `/notice` → 下一条消息作为内容 → 预览 + 确认按钮 → `copyMessage` 群发（不带「转发自」）。支持文本 / 图片 / 视频 / 文件，10 分钟未操作失效 |
| `/rm` | 仅第一主人 · 群内 | **回复要删的消息后发送 → 删除该消息**并秒撤回命令；结果双通道：群内 5 秒闪屏 + 完整审计私聊第一主人 |
| `/profile TGID` | 仅第一主人 · 群内 / 私聊 | **资料卡 + 7 项时间线**（申请 / 入群 / 退群 / 任命管理员 / 最早发言 / 最后发言 / 总入群）+ 黑名单与 GKY。群内身份先确认 bot 是该群管理员再查，「查不到」与「真的不在」严格区分 |
| `/health` | 仅第一主人 · 群内 / 私聊 | **运行检查两层**：状态自检（bot 身份 / D1 / 统计活性 / AI 绑定）+ 逐群体检（在不在群 / 是不是管理员 / 三权限 `can_delete_messages` `can_restrict_members` `can_invite_users`）；成本约 `1+2N` 次请求 |
| `/menu` | 仅第一主人 · 仅配置群内 | **群设置菜单页**，三入口（群统计 / 资料卡 / 运行检查），点入口原地切换、子页带「返回群设置」；**返回键只在第一主人打开时挂**（其他人进不了菜单，挂了就是死按钮） |
| `/search 关键词` `TGID` `@用户名` | 第一主人 · 全部群；该群**群主** · 仅本群 | **关键词搜索**带分页。关键词大小写不敏感、`LIKE` 走 `ESCAPE` 转义；`@用户名` 靠 `stat_speech` 反查 TGID，查不到就说查不到。**普通管理员 / 副主人 / 超管不可用**。边界：正文截断 200 字、命令消息不入库 |
| `/admins` | 仅主人私聊 | 分节列出主人 / 副主人 / 超管的 TGID、昵称、用户名、群内身份、来源群；单次 Telegram 查询上限 40 次 |
| `/blacklist` | 主人 / 副主人私聊 | 查看 D1 黑名单，最多 30 条，竖排分条 |
| `/job 任务ID [页码]` `/jobrun 任务ID` | 主人 / 副主人 | 查看与补跑批量任务（正常会自动续接到完成） |
| `/recent [N]` | 群内 / 私聊 | **捞回已被删的广告**：从 `moderation_messages` 按广告特征强度排序取最近 48 小时，冻结成快照私聊。群内可用但命令被撤回、列表只走私聊 |
| `/learnlast 序号` | 仅第一主人私聊 | 按**冻结快照**序号学习（不能重查实时数据，列表会因新消息挤动而错位），学习同时加黑 + 全群封禁；判错用回执里的 `/unban` 一键回滚 |
| `/addgroup` `/delgroup` `/listgroups` | 仅第一主人私聊 | 指令增删治理群（存 D1 `dynamic_groups`，不改环境变量；三道硬校验） |
| `/killer [on\|off\|status]` | 仅第一主人 · 群内 | 切换杀手模式：**ON = 全群封禁踢出**（含 `/ban` `/spam` 与自动处置）、**OFF = 仅永久禁言不踢出**（默认 OFF，需群在 `KILLER_MODE_GROUPS`）；非杀手群的 `/ban` `/spam` 恒为禁言，要踢人用 `/sban`；私聊 `/killer` 列出各群状态 |
| `/leavegroup -100xxxx` | 仅第一主人私聊 | 让 bot 真的退出群（与 `/delgroup` 区别：后者只停止治理） |
| `/dryrun [on\|off\|status]` | 仅第一主人 · 配置群内 | **演练模式**：判定照跑但不删不封不加黑不学习，命中写流水 + 私聊通知你，**通知带两个按钮当场拍板**（✅确认封 = 真处置 / ❌不该封 = 标误报只统计）。**群内回执发完即撤回、完整信息走私聊**（群里不留痕）；私聊 `/dryrun` 列出已开的群与命中数。**只挡处置不挡同款**：重发照删、`/spam` 连带照追。⚠️ 演练期间该群完全不设防 |
| `/add_ad_admin TGID` `/del_ad_admin TGID` | 仅第一主人私聊 | 授权 / 取消某成员发起 `/ad` 举报投票 |
| `/pending [N]` `/ignore 序号` `/rescreen [N]` `/adstats` | 仅第一主人私聊 | 广告检测复核与状态查询，见 [广告检测](#广告检测) |
| `/words [页码]` `/addword` `/delword` `/addsample` `/clearsamples` `/warmup` `/whitelist` | 仅第一主人私聊 | 指纹库、语义样本与域名白名单维护 |

### 自动化

| 行为 | 触发条件 | 说明 |
| --- | --- | --- |
| 黑名单实时拦截 | 黑名单用户在配置群发言 | 删消息 + 踢出 + 通知主人（禁言模式群跳过拦截） |
| 复入群踢回 | 黑名单用户被拉回 / 自加回 | 立即踢回（禁言模式群除外）；受保护角色（主 / 副 / 超管 / 任一群主管理员）不踢 |
| 手动封禁不同步 | 真人点 Telegram 封禁按钮 | **不写入 D1 黑名单**，仅发审计通知 |
| 手动解封封回 | 对象仍在 D1 黑名单 | 立即封回（群内手动解封无法绕过全局黑名单） |
| 通知带发起来源 | 自助解封回执 / 黑名单申诉通知 | 末尾一行 `📍 发起:私聊` 或 `📍 发起:群名 -100xxx`，一眼看出是在私聊发起还是在群里发起；`intercept`、成员处置类通知本就带 `📍 群：`，这次是补齐同款 |
| 广告自动处置 | 总分 ≥ `AD_SCORE_THRESHOLD` | 加黑 + 全群封禁 + 删消息 + 学指纹与 AI 样本 + 回执带 `/ignore` 序号与两个纠错按钮 |
| 演练模式 | 群内 `/dryrun` 开启 | 上面这条**一条都不执行**，命中只写流水 + 私聊通知（调阈值先看会封谁），通知上**点按钮当场拍板**：✅确认封 真处置、❌不该封 只标误报进统计。**只挡处置、不挡同款**：重发照样删、`/spam` 当场的连带与清扫照样追得到（命中消息仍进消息缓存，标 `is_ad` 所以进不了 `/search`），同款直封名单**不写** —— 那份名单命中会真封人。⚠️ 该群期间完全不设防 |
| 入群判定 | 有人进群（两条 update 路径都接） | **不等发言**：当场拉 bio + 查头像指纹，达线即封；每次检查都写 `ad_join_checks` 流水，正常号也记 |
| 正文图片判定 | 群里发图片 / 贴纸 / 动图 / 视频 / 文件 | 按 `file_unique_id` 查图片指纹：**同款素材**直接命中；首张登记后由 cron 识图判定，**单证只进观察**，`AD_IMAGE_VISION_DAILY` 控每日张数 |
| 资料挂载的频道/群/bot | 入群或闸二拉到 bio，且资料里有 `@xxx` / `t.me/xxx` | 查清目标的类型、标题、简介与**案底**：目标简介含招揽 +2、有案底（黑名单/曾被判过）+3；**查不到、简介为空、正常社群、挂个人号一律 0 分** —— 分界不在 `t.me` 这串字符上，而在被挂账号写没写招揽。每人最多查 5 个、按 handle 缓存 6 小时，**资料里没链接则零请求** |
| 转入观察 | 总分 ≥ `AD_OBSERVATION_SCORE` 但未及封禁线 | 写观察窗口，窗口内再发即累加；**正文不进 `/search` 检索源** |
| 批量任务自动续接 | 超出同步安全预算 | 转 D1 批量任务 + Queues 分片续接到完成 |
| 定时滚动复查 | cron（每天 2 次、日限 300 人） | 分档复查简介：进群 6 小时内每 2 小时一查，越往后越疏、3 天封顶；bio 没改且判据库没更新则跳过 |
| 统计剪枝 | cron | `stat_speech` / `stat_member` / `stat_actions` 按 180 天剪；入群 / 退群 / 申请明细**永久不剪** |

## 广告检测

### 三层判定怎么工作

| 层 | 干什么 | 阈值 |
| --- | --- | --- |
| ① 评分层 | 交易动词 / 业务词 / 结构特征 / 混淆签名累加打分 | 5 观察、7 封禁 |
| ② 指纹层 | 关键词、域名、用户名、简介四类指纹匹配 | `AD_FINGERPRINT_MIN_CONFIDENCE` = 0.6 |
| ③ AI 语义层 | `bge-m3` 向量相似度，抓改写过表述的广告 | `AD_AI_SIMILARITY_THRESHOLD` = 0.78 |
| ④ 形态 E 金额招揽 | **金额** 与 **收益/招人动作** 同现（「一天8000」「赚5万」「一单800」），结构判定不查词表 | **+5 只推到观察线，不直接封** |
| ⑤ 资料形状 | bio 归一化成形状哈希（换链接 / 换数字仍是同一形），被定罪过就记住 | **复用定罪 ≥ 2 次才 +3，只加分不定罪** |

三道闸：闸一 零成本评分定罪（含简介补查）、闸二 发言路径深度判定、闸三 定时滚动复查简介；入群即写名册，堵住「扫不到的号」的缺口。未绑 Workers AI 自动跳过第三层。

**豁免词条件化**（防广告拿豁免当挡箭牌）：`t.me`、`代理`、`h2` 这类豁免只保护纯技术文案；文案里出现**金额承诺、灰产词、强招揽构词**之一时豁免整体失效（`进群`、`cdn` 这类日常词**不**触发，技术群主照旧放行）。失效只撤销 −3 减分、**不加分**，定罪仍要过原有形态门槛。

**头像识别（与三层并行的一路）**：头像取自 `getChat` 的 `photo`，不额外花请求。判定分三档 —— 头像已定为广告图**且有其它佐证** → 封禁；**复用定罪 2 次以上** → 单独即可封；**单证** → 只进观察（头像可能被盗用，防止连坐）。被定罪者的头像自动入库（封禁在闸一时拿不到头像，走 cron 补学队列异步补），`/ignore` 纠错时同步清成干净，图上写着「看主页/赚钱」这类**由 moondream 视觉模型识图**判定（每日张数上限可配，设 `0` 即只跑指纹不调模型）。

**正文图片识别（同为并行的一路）**：图片、贴纸、动图、视频、文件消息按 `file_unique_id` 入库，同款素材复用即命中；**首张由 `moondream` 识图**，之后全靠指纹表零成本判。分档比头像严一档 —— **复用定罪 5 次以上**才单独封（群里转同一张梗图太常见），**单证**一律只进观察；`/ignore` 纠错同步清干净。设 `AD_IMAGE_VISION_DAILY=0` 即只跑指纹不调模型。

### 复核与纠错命令（仅第一主人私聊）

| 命令 | 干什么 |
| --- | --- |
| `/pending [N]` | 看待确认快照（得分、判据、资料） |
| `/ignore 序号` | **误封一键纠错**：解封 + 给命中指纹加误报，累计 3 次退役该指纹。封禁回执上等价的两个按钮：**↩️ 误判（回滚全部）**=本命令、**🔓 解封（判定维持）**=只把人放出来，指纹/样本/形状/快照一律不动 |
| `/rescreen [N]` | 重新筛查观察窗口里的可疑用户 |
| `/adstats` | 总览阈值、AI 状态、指纹与样本规模、头像与正文图片与会员标指纹库、观察窗口人数；后两屏是本群**入群检查流水**（每次进群都记，含正常号）与**演练状态**（含结论汇总：✅确认封 / ❌误报 / 待判各几条、误报最低分贴线时提示调 `AD_SCORE_THRESHOLD`） |

### 指纹库与样本库维护（仅第一主人私聊）

| 命令 | 干什么 |
| --- | --- |
| `/words [页码]` | 列指纹（命中、误报、置信度） |
| `/addword 值 [类型]` `/delword 值` | 增删一条指纹 |
| `/addsample 文本` `/clearsamples` | 增删 AI 样本 |
| `/warmup` | 补向量，每次 8 条，补满第三层才生效 |

### 阈值调优

| 情况 | 怎么办 |
| --- | --- |
| 平时 | **一个都别填**，用默认值 |
| 误封多 | `/ignore` 纠错，别急着调低阈值 |
| 漏封多 | `/adstats` 先确认三层都在跑、向量已补满 |
| 换 AI 模型 | 先 `/clearsamples` 清样本，旧向量维度不同会作废 |

## 前置条件

- 一个 Telegram Bot Token，通过 [@BotFather](https://t.me/BotFather) 创建。
- 一个 Cloudflare 账号，启用 Workers。
- 本地安装 Node.js 和 Wrangler，或直接使用 Cloudflare 控制台部署。跑离线测试需要 **Node 22+**（`node:sqlite` 内置模块要求）。
- 机器人需要被加入目标群组并设为管理员。
- Workers AI **可选**：绑定后广告检测启用第三层语义判定；不绑自动降级为两层，其余功能不受影响。免费层每天有一定的 Neurons 额度，`bge-m3` 是轻量嵌入模型（不是大语言模型），正常群规模不会超限。

建议给机器人以下权限：

- 封禁用户或解除封禁
- 管理员权限或限制成员权限
- 读取群成员状态
- 发送消息

> `chat_member` 事件订阅要求机器人是群管理员，否则收不到该事件 — 但本来部署就要求管理员权限，无需额外配置。

## 存储绑定

| 绑定 | binding 名 | 必需性 | 用途 |
| --- | --- | --- | --- |
| D1 Database | `DB` | **必需** | **唯一存储后端**。黑名单、清扫缓存、批量任务、投票状态、广告指纹库全部存 D1。表结构由代码自动建立，首次写入自动建表。 |
| Queue | `BULK_QUEUE` | 推荐 | `/ban` `/sban` `/spam` `/unban` 超出同步安全预算后的自动续接队列。注意这是 Cloudflare Queue 绑定，不是 `wrangler secret put` 环境变量。 |
| Workers AI | `AI` | 可选 | 广告检测第三层语义判定（`@cf/baai/bge-m3` 1024 维多语言嵌入模型）。不绑则自动降级为「评分 + 指纹」两层。 |

> **未绑定 D1** 或 D1 黑名单读取失败时，自助解封会失败关闭并拒绝继续，避免绕过全局黑名单。`/ban` `/sban` `/spam` `/unban` `/blacklist` 等命令会提示未绑定存储空间。
> **未绑定 `BULK_QUEUE`** 时，大批量任务仍会创建到 D1，但不会自动续接，需要管理员用 `/jobrun 任务ID` 手动补跑。
> **未绑定 `AI`** 时广告检测仍工作（评分 + 指纹两层），`/adstats` 会明确标注「未绑定，降级为评分 + 指纹两层」，不会静默失效。

| 广告检测 | `ad_learn_snapshots` | `/recent` 冻结的广告快照（供 `/learnlast` 按序号学习） |
| 广告检测 | `ad_avatars` | **头像指纹库**：主键 `big_file_unique_id`（官方保证跨时间跨 bot 稳定），记判决 / 复用定罪次数 / 下载句柄。`verdict` = `pending` 待识别、`ad` 广告图、`clean` 已排除 |
| 广告检测 | `ad_images` | **正文图片指纹库**：主键 `file_unique_id`，多一列 `kind`（`photo` / `sticker` / `animation` / `video` / `document`，只有前两者进视觉识别队列）。`verdict` 三态与 `ad_avatars` 完全一致，`/ignore` 纠错口径也一致 |
| 广告检测 | `ad_badges` | **同款会员标指纹库**：主键 `emoji_status_custom_emoji_id`（`getChat` 顺带返回，零额外请求）。**不做视觉识别**，没有 `file_id` / `vision_checked_at` 两列；`verdict` 三态与 `ad_avatars` 一致，同款定罪 3 次起才参与定罪 |
| 广告检测 | `ad_spam_texts` | 同款直封名单（正文哈希，`/spam` 学入后直发即删 + 封）。**按需建立** |
| 广告检测 | `ad_profile_shapes` | **资料形状库**：bio 归一化哈希 + 复用定罪次数，给同模板批量号跨账号加分 |
| 广告检测 | `ad_dryrun_log` | **演练命中流水**：得分、阈值、判据（`reasons`）+ **整份判定 `evaluation`**（按钮确认封时原样回放给处置链）+ **`fp` / `done`**（主人点按钮留下的两个结论，`/adstats` 的结论汇总取自它们），保留 30 天。**按需建立**，不进完整性复验 |
| 广告检测 | `ad_join_checks` | **入群检查流水**：每次进群都记，含判为正常的（能看到「检查过、这个人正常」），保留 30 天。**按需建立** |
| 广告检测 | `ad_link_cache` | **资料挂载链接解析缓存**：handle（小写主键）→ 类型、标题、简介、案底，6 小时过期 —— 群里十个人挂同一个频道只查一次。**按需建立**，不进完整性复验 |

> **广告检测的表走独立初始化路径**，与核心 5 表完全隔离，`D1_SCHEMA_VERSION` 保持 `8` 不变 —— 老部署升级后现有黑名单数据**一条都不会动**。建表失败时整个广告层静默跳过并进入 60 秒冷却（避免 D1 抖动时每条消息都重试迁移耗尽子请求预算），既有功能不受任何影响。

## 部署

### 1. 安装 Wrangler

```bash
npm install -g wrangler
wrangler login
```

### 2. 创建 D1 数据库

```bash
wrangler d1 create tg-unban-bot-plus
```

把返回的 `database_id` 填进 `wrangler.toml` 的 `[[d1_databases]]`，`binding` 必须是 `DB`。

### 3. 创建批量任务 Queue

```bash
wrangler queues create tg-unban-bot-plus-bulk
```

绑定名必须是 `BULK_QUEUE`。

### 4. 绑定 Workers AI（可选，广告检测第三层）

`wrangler.toml` 加 `[ai]` 段、`binding = "AI"`；Dashboard 部署则在 **设置 → 绑定 → 添加绑定 → Workers AI**，名字必须正好是 `AI`。不绑则降级两层。

### 5. 启用 Observability（可选）

`wrangler.toml` 加 `[observability.logs] enabled = true` —— 回执只有中文原因，**英文原文在 Worker 日志**。

### 6. 设置环境变量

完整清单见 [环境变量](#环境变量)。下面只列关键点。

#### 6.1 最小可用配置（3 个必填项）

```bash
wrangler secret put TOKEN        # 你定的随机字符串，用作 HTTP 接口密码
wrangler secret put BOT_TOKEN    # BotFather 给的 token
wrangler secret put GROUP_ID     # -1001234567890（可逗号分隔多群）
```

#### 6.2 推荐加上（强烈建议）

`OWNER_IDS` —— 主人 + 副主人 TGID，**第一个是主人**；不填则不发任何私聊通知。

#### 6.3 自助解封文案与主群（可选）

`SELF_UNBAN_KEYWORD` `START_WELCOME` `SELF_UNBAN_PROMPT` `SELF_UNBAN_APPROVED` `_NOLINK` `SELF_UNBAN_CONTACT_GROUP`，默认值见源码顶部。

#### 6.4 其它可选项

`SUPER_ADMIN_IDS` `KILLER_MODE_GROUPS` `STAT_SEARCH_GROUPS` `PROFILE_LOOKUP_GROUPS` `STATIC_USER_PROFILES` `BLACKLIST_PAGE_LIMIT` `GKY_BANLIST_ENDPOINT` `FLASH_MESSAGE_TTL_MS` `MSG_CACHE_SIZE` `STATS_TZ_OFFSET`。

#### 6.5 广告检测阈值与开关（可选，**建议一个都不填**）

`AD_SCORE_THRESHOLD` `AD_OBSERVATION_SCORE` `AD_OBSERVATION_HOURS` `AD_AI_SIMILARITY_THRESHOLD` `AD_AI_TOP_K` `AD_FINGERPRINT_MIN_CONFIDENCE` `AD_ENRICH_EVERY` `AD_ENRICH_MIN_OCCURRENCE` `AD_ENRICH_MAX_RESULTS` `AD_CARD_KILL` `AD_AVATAR_VISION_DAILY` `AD_IMAGE_VISION_DAILY` `AD_PROTECTED_USERNAMES` `AD_TRUSTED_BOTS` —— 用默认值，理由见 [阈值调优](#阈值调优)。 `AD_JOIN_SCORE_THRESHOLD`

#### 6.6 完整配置示例（可直接照抄改值）

```bash
wrangler secret put TOKEN
wrangler secret put BOT_TOKEN
wrangler secret put GROUP_ID
wrangler secret put OWNER_IDS
wrangler secret put SUPER_ADMIN_IDS
wrangler secret put KILLER_MODE_GROUPS
wrangler secret put STAT_SEARCH_GROUPS
wrangler secret put GKY_BANLIST_ENDPOINT
```

取值与含义见 [环境变量](#环境变量)。

#### 6.7 老部署升级需要做什么

| 项 | 处理 |
| --- | --- |
| `wrangler.toml` | 确认 `keep_vars = true`，否则部署会用本地覆盖远端变量 |
| 数据 | 无需手动 SQL，表结构自动迁移，黑名单一条不动 |
| 订阅 | 改过 `allowed_updates` 必须**重新访问一次初始化地址** |
| AI | 绑了 AI 记得发几次 `/warmup` 补满向量 |

### 7. 部署 Worker

```bash
wrangler deploy
```

Workers 已连 GitHub 时，`git push` 即自动部署。

### 8. 初始化 Webhook

浏览器访问 `https://你的Worker域名/{TOKEN}` —— 这一步**注册 Webhook + 下发 `allowed_updates` + 注册命令菜单**。改过 `allowed_updates` 必须重访一次，否则新类型不推送。
## 使用方法

### 用户自助解封

| 步骤 | 用户操作 | 机器人响应 |
| --- | --- | --- |
| 1 | 私聊发 `/unban` | 返回自助解封检查清单 |
| 2 | 复制 `<code>` 里**整句**并发送 | 逐字整句匹配（多 / 少标点、夹带字符一律拒绝） |
| 3 | — | 解封全部配置群 → 成功回执 + 主群「联系管理员」按钮 |

在 D1 全局黑名单中的用户第一道闸就被拦（**永久封禁，只能 `/unban` 移除**）。

### 二次审核流程

| 按钮 | 复制内容 | 谁来发 |
| --- | --- | --- |
| **📋 点击复制 GKY 添加白名单代码** | 两行 `GKYbotSave\n用户ID` | **真人管理员**粘贴到封禁记录对应的群发送 |
| **📋 点击复制 本地解封命令** | `/unban 用户ID` | 有权限的管理员发送（复制本身不改 D1） |

复制按钮只进剪贴板，**机器人不会自动代发**（GKY 不认其它 Bot 代发的 `GKYbotSave`）。

## 常见问题

### Q1：访问 `/{TOKEN}` 返回 500，或部署后 Webhook 不工作
`TOKEN` / `BOT_TOKEN` / `GROUP_ID` 缺一不可 —— `wrangler secret list` 核对，改完重新访问初始化地址。
### Q2：用户在私聊发了正确确认句却没被解封
必须**完整逐字粘贴**整句，多 / 少标点都会被拒；改过确认句要用当前生效那句。
### Q3：机器人收不到群里管理员手动封/解封的同步信号
bot 必须是**群管理员**，然后重新访问初始化地址重订 webhook。
### Q4：为什么点击复制后 GKY 不会自动处理
复制只进剪贴板，GKY 不认其它 Bot 代发 —— 由**真人管理员**粘贴发送。
### Q5：D1 绑定后黑名单或批量任务为空
确认 `binding` 是 `DB`、`database_id` 对得上；新部署还没有批量任务属正常。
### Q6：`/banlist?tgid=...` 返回失败或无数据
依赖外部服务 `GKY_BANLIST_ENDPOINT`，外部不可用时等恢复或换后端（HTML 须与 `parseBanlistHTML` 兼容）。
### Q7：修改了 `_worker.js` 顶部的 `DEFAULT_*` 默认值，但没生效
**环境变量优先级更高**，后台已填同名变量就盖住源码；改源码要 `wrangler deploy`。
### Q8：管理员命令（`/ban` `/spam` `/check` `/blacklist`）没反应
`/ban` `/spam` `/check` 的鉴权是「**任一配置群**的管理员或群主」；`/blacklist` 只能私聊发。`/sban` 更严：限第一主人、副主人、该群群主，私聊仅第一主人与副主人，其余人在群里**完全静默**。
### Q9：部署后环境变量被意外重置
本项目 `wrangler.toml` 已设 `keep_vars = true`；fork 后改过记得改回来。
### Q10：自助解封通过后，用户为什么还是不能在群里发言
三种情况：`kicked` 要重新加群、被其它系统限言、在 GKY 全局黑名单（会触发二次审核提醒）。
### Q11：`/ban` `/sban` `/spam` `/unban` 批量超过 50 个怎么办
单次上限 50，超过拆批；预算不足的自动转批量任务。
### Q12：`/{TOKEN}/export` 接口怎么用，安不安全
受 `TOKEN` 保护（不匹配返回 405）；浏览器看表、`?format=json` / `?format=csv` 下载。
### Q13：`/ban` `/sban` `/spam` 显示「Telegram 封禁失败 0/N（检查bot封禁权限）」
去群设置 → 管理员 → 本机器人，打开**封禁用户**（禁言与踢出都靠它）；`/sban` 撤回历史发言另需**删除消息**。
### Q14：黑名单用户的旧消息怎么办，会被自动删吗
踢出（`/sban`、自动处置、杀手 ON 群）时 `revoke_messages` 自动撤回**最近 48 小时**，这是平台上限，更早的只能手动删。`/ban` 禁言不撤回消息 —— 要清历史，引用回复 `/spam`，或在群里对单个 TGID 发 `/ban` 顺带清扫当前群。
### Q15：群里发了 /ban 或 /spam 但第一主人没收到详情
先私聊 bot 发一次 `/start` 建立会话，并核对 `OWNER_IDS[0]` 是第一主人。
### Q16：管理命令在群里还会发 5 秒闪屏吗
不会 —— 群内只发简洁汇总，完整明细私聊第一主人。
### Q17：群管理员在群里发命令，自己能收到详情吗
群内发令者不收完整详情，**私聊执行时自己收到**。
### Q18：配置了 OWNER_IDS 但主人/副主人收不到通知
bot 不能主动给没聊过的人发私信 —— 各账号私聊发一次 `/start`。
### Q19：操作人标签会显示"主人"/"副主人"/"群管理员"，怎么判断
`OWNER_IDS[0]` 标主人、其余标副主人，剩下按调用上下文兜底标管理员。
### Q20：隐藏指令对其他人真的完全无反应吗
是 —— 未授权者**群内完全静默**，私聊才回「权限不足」；按钮点击时重新验权限。
### Q21：管理员置顶消息后，置顶被 bot 删除并取消了
v2 已修复；旧版升级后需**清一次存量缓存**。
### Q22：Windows 下 `git push` 报 `ServicePointManager 不支持具有 socks5 方案的代理`
不是本项目问题 —— 把 git 代理改成 `http://127.0.0.1:端口`。
### Q23：频道置顶的内容在关联讨论群被 bot 删除并取消置顶（与 Q21 不同的第二个成因）
Q21 是服务消息被清扫缓存误删，本条是**频道转发消息本身**被广告检测删掉，路径不同。
### Q24：正常用户被广告检测误封了怎么办
`/pending` 拿序号 → `/ignore 序号`：一键解封 + 给命中指纹加误报，累计 3 次该指纹自动退役。
### Q25：广告号没被检测到怎么办
引用回复 `/spam` 最快（自动学指纹）；手工加 `/addword`；被抢先删的用 `/recent` + `/learnlast`。
### Q26：`/adstats` 显示「未绑定，降级为评分 + 指纹两层」
Workers AI 没绑上 —— `wrangler.toml` 加 `[ai]` 段，绑定名必须**正好是** `AI`。
### Q27：广告检测的 13 张表建失败了会怎样
**既有功能完全不受影响**，广告层静默跳过并进 60 秒冷却；用 `/adstats` 诊断。
### Q28：`/admins` 里某个权限人显示「昵称:未获取 用户名:未获取」
Bot API **只能查 bot 所在群的成员** —— 把 bot 拉进对方所在的群填 `PROFILE_LOOKUP_GROUPS`，或用 `STATIC_USER_PROFILES` 填静态资料。
### Q29：处置完广告后，广告正文又被某个 bot 带引用重新贴回群里
已拆两条通道：**bot 发的广告 → 删 + 封**；**已处置正文的重发 → 只删不封**。
### Q31：同款连带查杀漏掉了某个号，或者广告号过一阵又发同款
同款按正文哈希反查，文字有细微差别就查不到 —— 第一主人回复广告发 `/spam`，该文案进**同款直封**名单后直发即删 + 封。
### Q30：回执里只显示中文原因，想看 Telegram 返回的英文原文去哪看
英文原文在 **Cloudflare 后台 → Workers → 本 Worker → 日志**。
