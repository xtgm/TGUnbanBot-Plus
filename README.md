基于 Cloudflare Workers 的 Telegram 群组自助解封与反广告机器人：用户私聊自助解封（GKY + 本地 D1 双库查询、解封命令复制、群内举报投票、新机器人风控），广告号由四层检测自动识别并封禁。

单文件 `_worker.js`，D1 一个绑定跑全部存储，34 条命令。

## 与原项目的差异

- **D1 唯一存储后端** —— 黑名单 / 清扫缓存 / 批量任务 / 投票 / 指纹全存 D1（无 KV 依赖，免费层 10 万次/天写入不溢出）；黑名单结构 `["123"]` → `[{id, reason, by, at}]`，旧裸数组自动归一化，**零迁移**
- **多群组 + 动态群组** —— `GROUP_ID` 逗号分隔（第一条为主群）；`/addgroup` `/delgroup` `/listgroups` 存 D1 可改，三道硬校验，动态群永不顶替主群
- **批量任务** —— 四条命令支持多 TGID（半角/全角逗号、空格、换行、`[123,456]`），超出同步预算自动转 D1 + Queues 分片续接，单次 ≤50
- **加黑即执行**（原项目只写库不踢人）—— `/ban` `/spam` 加黑后**立即遍历全部群禁言**、`/sban` **立即全群踢出**；黑名单用户发言实时拦截删消息 + 踢人，复入群立即踢回
- **黑名单来源收紧** —— 写入来源**只有真人执行的管理命令**，原生按钮与第三方机器人一律不写；**永不自助解封**，只能 `/unban` 移除。`chat_member` 事件订阅另使群内手动封禁不写黑名单（仅审计通知）、手动解封时封不回黑名单用户
- **通知与回执** —— `OWNER_IDS[0]` 收全部通知、其余副主人收加黑踢出，末尾标 `📍 发起:` 来源；解封回执改**主群内联按钮**（不再给点不动的假链接），`SELF_UNBAN_CONTACT_GROUP` 可指定；黑名单用户发 `/start` 给介绍、发 `/unban` 被闸门拒；重复举报预检在目标已封且已入 D1 时静默跳过
- **素材指纹四类**（本项目新增的整层）—— 头像 / 正文图片 / 会员标 / 自定义贴纸 emoji，取自已有的 `getChat` 与消息 `entities`（**零额外请求**），`moondream` 识图读图内文字，`/ignore` 同步纠错；正文图片以前**整条不进检测**（caption 空就被早退闸门丢掉），现在按 `file_unique_id` 入库复用
- **单证只进观察** —— 会员标**同款定罪 3 次起且有佐证**、正文图片**复用 5 次**、头像**复用 2 次**才单独封，防素材被盗用连坐
- **emoji 切断关键词** —— 「点⚔️查」骨架命中**且有承诺/招揽语境才计分**，只有骨架一律不计分（正常人也发「点👍看」）
- **资料挂载的频道/群/bot** —— **先判人再查链接**，简介含招揽 +2、有案底 +3（案底含**自举**），查不到/简介空/正常社群/挂个人号一律 0 分
- **新增命令与展示** —— `/stats` 统计面板、`/search` 关键词搜索、`/profile` 资料卡时间线、`/health` 两层自检、`/menu` 群设置菜单、`/recent` + `/learnlast` 捞回并学习已删广告；`/ad` 投票**通过后昵称脱敏为「首字\*\*\*尾字」**防借卡片二次传播；`/check` 双库独立查询、`/blacklist` 竖排分条、`/help` 分区裸文本

## 功能

### 普通用户

- `/start` —— 私聊欢迎语（`START_WELCOME`，支持 HTML 子集）
- `/unban` —— **自助解封**：返回检查清单，粘贴 `SELF_UNBAN_KEYWORD` **完整整句**才触发（多/少标点即拒），走全部配置群，回执含主群「联系管理员」按钮
- `/start check_用户ID` —— 二次审核入口（机器人自动生成的深链）

### 群管理员

- `/ban 用户ID [原因]` —— 加 D1 黑名单 + 遍历全部群**永久禁言**（杀手 ON 群为踢出），支持批量；群内撤回命令、详情私聊第一主人；群内对单个 TGID 顺带清扫当前群
- `/sban 用户ID [原因]` —— 加黑名单 + 遍历全部群**踢出并撤回其发言**；`/ban` 改禁言后要踢人就用这条；**群里不留痕**，逐群明细只走私聊
- `/spam [用户ID] [原因]` —— 同上（`reason=spam`，**全群禁言**）+ 删除被回复的垃圾消息
- `/unban 用户ID` —— 先删 D1 记录成功才解封；每群执行「恢复发言 + 解除封禁」两步（同一个人可能部分群被踢、部分群被禁言）
- `/check TGID` —— 查 GKY + 本地黑名单，输出**资料卡 + 时间线**；群内不撤回命令、结果留群里并私聊第一主人
- `/stats [范围]` —— 统计面板：活跃 / 增长 / 风控，带时间切换与 7/30 天趋势。范围支持 `today` `week` `month` `昨天` `上周` `近7天` `2026-09-10` 及日期区间。**广告不计入发言统计**
- `/ad [原因]` —— 隐藏举报投票，赞成反对**各 6 票**（`AD_VOTE_THRESHOLD`），任一配置群管理员一票定音；发起人自动算 1 票、可改投去重；命令发出即删

### 主人/副主人专属(`OWNER_IDS`)— 隐藏指令

**仅第一主人私聊**

- `/help` —— 分区列出全部命令，一条一行，权限写在分区标题
- `/notice` —— **全体通知**：发命令 → 下一条消息作内容 → 预览 + 确认 → `copyMessage` 群发（不带「转发自」），支持文本/图片/视频/文件，10 分钟未操作失效
- `/rm` —— 回复消息后发送 → 删除该消息并秒撤回命令；群内 5 秒闪屏 + 完整审计走私聊
- `/profile TGID` —— **资料卡 + 7 项时间线**（申请/入群/退群/任命/最早发言/最后发言/总入群）+ 黑名单与 GKY
- `/admins` —— 分节列出主人/副主人/超管的 TGID、昵称、用户名、群内身份、来源群（单次查询上限 40 次）
- `/learnlast 序号` —— 按**冻结快照**序号学习（列表会因新消息挤动而错位），同时加黑 + 全群封禁；判错用回执的 `/unban` 回滚
- `/addgroup` `/delgroup` `/listgroups` —— 指令增删治理群（存 D1，三道硬校验，不改环境变量）
- `/add_ad_admin TGID` `/del_ad_admin TGID` —— 授权 / 取消某成员发起 `/ad` 投票
- `/pending [N]` `/ignore 序号` `/rescreen [N]` `/adstats` —— 广告检测复核与状态，见 [广告检测](#广告检测)
- `/words [页码]` `/addword` `/delword` `/addsample` `/clearsamples` `/warmup` `/whitelist` —— 指纹库、语义样本与域名白名单维护
- `/leavegroup -100xxxx` —— 让 bot 真的退出群（`/delgroup` 只停止治理）

**第一主人 · 群内或私聊**

- `/health` —— 运行检查两层：状态自检（bot 身份 / D1 / 统计活性 / AI 绑定）+ 逐群体检（在不在群、是否管理员、三权限），成本约 `1+2N` 次请求
- `/menu` —— **群设置菜单页**，三入口（群统计 / 资料卡 / 运行检查），点入口原地切换；返回键只在第一主人打开时挂
- `/search 关键词` `TGID` `@用户名` —— 关键词搜索带分页，大小写不敏感、`LIKE` 走 `ESCAPE` 转义；**普通管理员 / 副主人 / 超管不可用**
- `/killer [on|off|status]` —— 杀手模式：**ON = 全群封禁踢出**（含自动处置）、**OFF = 仅永久禁言**（默认，需群在 `KILLER_MODE_GROUPS`）；非杀手群的 `/ban` `/spam` 恒为禁言，要踢人用 `/sban`
- `/dryrun [on|off|status]` —— **演练模式**：判定照跑但不删不封不加黑不学习，命中写流水 + 私聊通知**带两个按钮当场拍板**（✅确认封 / ❌不该封）。群内回执发完即撤；**只挡处置不挡同款**（重发照删、`/spam` 连带照追）。⚠️ 演练期间该群完全不设防
- `/recent [N]` —— 捞回已被删的广告：按广告特征强度取最近 48 小时，冻结成快照私聊

**主人 + 副主人**

- `/blacklist` —— 查 D1 黑名单，最多 30 条，竖排分条
- `/job 任务ID [页码]` `/jobrun 任务ID` —— 查看与补跑批量任务（正常会自动续接到完成）

### 自动化

- **黑名单实时拦截** —— 黑名单用户在配置群发言即删消息 + 踢出 + 通知主人（禁言模式群跳过）
- **复入群踢回** —— 黑名单用户被拉回 / 自加回立即踢回；受保护角色（主/副/超管/任一群主管理员）不踢
- **手动封禁不同步** —— 真人点 Telegram 封禁按钮**不写 D1 黑名单**，仅发审计通知；手动解封时对黑名单用户**立即封回**（无法绕过全局黑名单）
- **通知带发起来源** —— 末尾一行 `📍 发起:私聊` 或 `📍 发起:群名 -100xxx`
- **广告自动处置** —— 总分 ≥ `AD_SCORE_THRESHOLD` 即加黑 + 全群封禁 + 删消息 + 学指纹与 AI 样本，回执带 `/ignore` 序号与两个纠错按钮
- **演练模式** —— `/dryrun` 开启后上面这条一条都不执行，只写流水 + 私聊通知；**只挡处置不挡同款**（重发照删、`/spam` 连带照追，但同款直封名单不写）
- **入群判定** —— 不等发言：进群当场拉 bio + 查头像指纹，达线即封；每次检查都写 `ad_join_checks` 流水，正常号也记
- **资料挂载的频道/群/bot** —— **先判人再查链接**：资料卡与正文都没广告特征的正常人**一个请求都不花**；查的人按目标的简介与案底打分（简介含招揽 +2、有案底 +3，案底含**自举**），查不到/简介空/正常社群/挂个人号一律 0 分。每人最多查 5 个、按 handle 缓存 6 小时
- **转入观察** —— 总分 ≥ `AD_OBSERVATION_SCORE` 但未及封禁线时写观察窗口，窗口内再发即累加；**正文不进 `/search` 检索源**
- **批量任务自动续接** —— 超出同步安全预算转 D1 批量任务 + Queues 分片续接
- **定时滚动复查** —— cron 每天 2 次、日限 300 人，按进群时长分档复查简介（6 小时内每 2 小时一查，3 天封顶）；bio 没改且判据库没更新则跳过
- **统计剪枝** —— `stat_speech` / `stat_member` / `stat_actions` 按 180 天剪；入群/退群/申请明细**永久不剪**

## 广告检测

### 三层判定怎么工作

| 层 | 干什么 | 阈值 |
| --- | --- | --- |
| ① 评分层 | 交易动词 / 业务词 / 结构特征 / 混淆签名累加打分 | 5 观察、7 封禁 |
| ② 指纹层 | 关键词、域名、用户名、简介四类指纹匹配 | `AD_FINGERPRINT_MIN_CONFIDENCE` = 0.6 |
| ③ AI 语义层 | `bge-m3` 向量相似度，抓改写过表述的广告 | `AD_AI_SIMILARITY_THRESHOLD` = 0.78 |
| ④ 形态 E 金额招揽 | **金额** 与 **收益/招人动作** 同现（「一天8000」「赚5万」「一单800」），结构判定不查词表 | **+5 只推到观察线，不直接封** |
| ⑤ 资料形状 | bio 归一化成形状哈希（换链接 / 换数字仍是同一形），被定罪过就记住 | **复用定罪 ≥ 2 次才 +3，只加分不定罪** |

三道闸：闸一 零成本评分定罪（含简介补查）、闸二 发言路径深度判定、闸三 定时滚动复查简介；入群即写名册，堵住「扫不到的号」的缺口。未绑 Workers AI 自动跳过第三层。

**豁免词条件化**（防广告拿豁免当挡箭牌）：`t.me`、`代理`、`h2` 这类豁免只保护纯技术文案；文案里出现**金额承诺、灰产词、强招揽构词**之一时豁免整体失效（`进群`、`cdn` 这类日常词**不**触发，技术群主照旧放行）。失效只撤销 −3 减分、**不加分**，定罪仍要过原有形态门槛。

**头像识别（与三层并行的一路）**：头像取自 `getChat` 的 `photo`，不额外花请求。判定分三档 —— 头像已定为广告图**且有其它佐证** → 封禁；**复用定罪 2 次以上** → 单独即可封；**单证** → 只进观察（头像可能被盗用，防止连坐）。被定罪者的头像自动入库（封禁在闸一时拿不到头像，走 cron 补学队列异步补），`/ignore` 纠错时同步清成干净，图上写着「看主页/赚钱」这类**由 moondream 视觉模型识图**判定（每日张数上限可配，设 `0` 即只跑指纹不调模型）。

**正文图片识别（同为并行的一路）**：图片、贴纸、动图、视频、文件消息按 `file_unique_id` 入库，同款素材复用即命中；**首张由 `moondream` 识图**，之后全靠指纹表零成本判。分档比头像严一档 —— **复用定罪 5 次以上**才单独封（群里转同一张梗图太常见），**单证**一律只进观察；`/ignore` 纠错同步清干净。设 `AD_IMAGE_VISION_DAILY=0` 即只跑指纹不调模型。

### 管理命令（仅第一主人私聊）

**复核与纠错**
- `/pending [N]` —— 待确认快照（得分、判据、资料）
- `/ignore 序号` —— **误封一键纠错**：解封 + 给命中指纹加误报，累计 3 次退役该指纹。封禁回执上等价的两个按钮：**↩️ 误判（回滚全部）** = 本命令、**🔓 解封（判定维持）** = 只把人放出来，指纹/样本/形状/快照/链接案底一律不动
- `/rescreen [N]` —— 重新筛查观察窗口里的可疑用户
- `/adstats` —— 阈值、AI 状态、指纹与样本规模、头像/图片/自定义 emoji 三类素材库、观察窗口人数；后两屏是本群入群检查流水与演练状态（含结论汇总，误报最低分贴线时提示调 `AD_SCORE_THRESHOLD`）

**指纹库与样本库维护**
- `/words [页码]` —— 列指纹（命中、误报、置信度）；`/addword 值 [类型]` `/delword 值` 增删一条
- `/addsample 文本` `/clearsamples` —— 增删 AI 样本
- `/warmup` —— 补向量，每次 8 条，补满第三层才生效
- `/whitelist [子命令]` —— 域名白名单管理

### 阈值调优与运维

- **平时一个都别填**，用默认值
- **误封多** → `/ignore` 纠错，别急着调低阈值；**漏封多** → `/adstats` 先确认三层都在跑、向量已补满
- **换 AI 模型** → 先 `/clearsamples` 清样本，旧向量维度不同会作废
- 部署后发 `/adstats` 确认表与种子已建，绑了 AI 再发几次 `/warmup` 补满向量
- 发现漏放：引用回复 `/spam` 最快；被抢先删的用 `/recent` + `/learnlast`
- 校准阈值：先开 `/dryrun` 看会封谁，再用 `/pending` 复核（**测试证明不了阈值设得对**）
 |

- **优先级** —— 环境变量 > 源码默认值：Cloudflare 后台已填同名变量时，改源码不生效

## 存储绑定

| 绑定 | binding 名 | 必需性 | 用途 |
| --- | --- | --- | --- |
| D1 Database | `DB` | **必需** | **唯一存储后端**。黑名单、清扫缓存、批量任务、投票状态、广告指纹库全部存 D1。表结构由代码自动建立，首次写入自动建表。 |
| Queue | `BULK_QUEUE` | 推荐 | `/ban` `/sban` `/spam` `/unban` 超出同步安全预算后的自动续接队列。注意这是 Cloudflare Queue 绑定，不是 `wrangler secret put` 环境变量。 |
| Workers AI | `AI` | 可选 | 广告检测第三层语义判定（`@cf/baai/bge-m3` 1024 维多语言嵌入模型）。不绑则自动降级为「评分 + 指纹」两层。 |

> **未绑定 D1** 或 D1 黑名单读取失败时，自助解封会失败关闭并拒绝继续，避免绕过全局黑名单。`/ban` `/sban` `/spam` `/unban` `/blacklist` 等命令会提示未绑定存储空间。
> **未绑定 `BULK_QUEUE`** 时，大批量任务仍会创建到 D1，但不会自动续接，需要管理员用 `/jobrun 任务ID` 手动补跑。
> **未绑定 `AI`** 时广告检测仍工作（评分 + 指纹两层），`/adstats` 会明确标注「未绑定，降级为评分 + 指纹两层」，不会静默失效。

### D1 表结构（全部自动建立，无需手动 SQL）

- **核心 5 张** —— `schema_meta` schema 版本号（当前 `8`）、`blacklist` 全局黑名单（TGID / 原因 / 操作人 / 时间 / 备注）、`moderation_messages` 群消息缓存（`/spam` `/ban` 清扫历史发言与**同款连带反查**；被判过的广告标 `is_ad=1`，`/spam` 追得到、`/search` 检索不到）、`batch_jobs` 批量任务状态与游标、`dynamic_groups` 动态治理群
- **统计 4 张** —— `stat_speech` `stat_member` `stat_actions` 按天计数（`/stats` 数据源）、`stat_member_events` 入群/退群/申请**明细**（`/profile` 时间线，**永久不剪枝**）
- **按需建立 4 张** —— `ad_votes` `ad_vote_allowlist`（`/ad` 投票）、`killer_mode`、`dryrun_groups`
- **广告检测 17 张** —— 判定：`ad_fingerprints` 指纹库（keyword/domain/username/bio 四类）、`ad_user_screening` 观察窗口、`ad_sample_embeddings` AI 样本与向量、`ad_domain_whitelist` 域名白名单、`ad_profile_shapes` 资料形状库、`ad_spam_texts` 同款直封名单；**素材指纹三张**：`ad_avatars` 头像、`ad_images` 正文图片（多一列 `kind`，只有 photo/sticker 进视觉识别）、`ad_badges` 会员标 + 正文贴纸 emoji（同一 id 体系共用一张表与同一道安全阀）—— 三者 `verdict` 同为 `pending`/`ad`/`clean` 三态，`/ignore` 纠错口径一致；**流程**：`ad_group_members` 名册、`ad_scan_state` 滚动复查游标、`ad_learn_snapshots` `/recent` 冻结快照、`ad_confirm_tokens` 二次确认令牌、`ad_join_checks` 入群检查流水（含正常号，留 30 天）、`ad_dryrun_log` 演练命中流水（含整份 `evaluation` 供按钮回放，留 30 天）、`ad_pending_snapshots` 待复核快照（**100 年不过期**，`/ignore` 后置 `expires_at=0` 不再算案底）、`ad_link_cache` 资料挂载链接解析缓存（两本案底 `ad_known` 查用户黑名单、`ad_confirmed` 自举标记，按 `fetched_at` 6 小时过期）

后两张按需建立、不进完整性复验。

> **广告检测的表走独立初始化路径**，与核心 5 表完全隔离，`D1_SCHEMA_VERSION` 保持 `8` 不变 —— 老部署升级后现有黑名单数据**一条都不会动**。建表失败时整个广告层静默跳过并进入 60 秒冷却（避免 D1 抖动时每条消息都重试迁移耗尽子请求预算），既有功能不受任何影响。

## 部署

### 1. 安装 Wrangler

```bash
npm install -g wrangler
wrangler login
```

### 2. 创建 D1 数据库

```bash
wrangler d1 create tg-unban-bot-plus
```

把返回的 `database_id` 填进 `wrangler.toml` 的 `[[d1_databases]]`，`binding` 必须是 `DB`。

### 3. 创建批量任务 Queue

```bash
wrangler queues create tg-unban-bot-plus-bulk
```

绑定名必须是 `BULK_QUEUE`。

### 4. 绑定 Workers AI（可选，广告检测第三层）

`wrangler.toml` 加 `[ai]` 段、`binding = "AI"`；Dashboard 部署则在 **设置 → 绑定 → 添加绑定 → Workers AI**，名字必须正好是 `AI`。不绑则降级两层。

### 5. 启用 Observability（可选）

`wrangler.toml` 加 `[observability.logs] enabled = true` —— 回执只有中文原因，**英文原文在 Worker 日志**。

### 6. 设置环境变量

完整清单见 [环境变量](#环境变量)。下面只列关键点。

#### 6.1 最小可用配置（3 个必填项）

```bash
wrangler secret put TOKEN        # 你定的随机字符串，用作 HTTP 接口密码
wrangler secret put BOT_TOKEN    # BotFather 给的 token
wrangler secret put GROUP_ID     # -1001234567890（可逗号分隔多群）
```

#### 6.2 推荐加上（强烈建议）

`OWNER_IDS` —— 主人 + 副主人 TGID，**第一个是主人**；不填则不发任何私聊通知。

**可选** —— 解封文案 `SELF_UNBAN_KEYWORD` `START_WELCOME` `SELF_UNBAN_PROMPT` `SELF_UNBAN_APPROVED` `_NOLINK` `SELF_UNBAN_CONTACT_GROUP`；群与权限 `SUPER_ADMIN_IDS` `KILLER_MODE_GROUPS` `STAT_SEARCH_GROUPS` `PROFILE_LOOKUP_GROUPS` `STATIC_USER_PROFILES`；其它 `BLACKLIST_PAGE_LIMIT` `GKY_BANLIST_ENDPOINT` `FLASH_MESSAGE_TTL_MS` `MSG_CACHE_SIZE` `STATS_TZ_OFFSET`；广告阈值 `AD_*`（含 `AD_JOIN_SCORE_THRESHOLD`）**建议一个都不填**，理由见 [阈值调优与运维](#阈值调优与运维)。默认值见源码顶部 `=可修改=` 区段。
`

#### 6.3 老部署升级需要做什么

- **`wrangler.toml`** —— 确认 `keep_vars = true`，否则部署会用本地覆盖远端变量


浏览器访问 `https://你的Worker域名/{TOKEN}` —— 这一步**注册 Webhook + 下发 `allowed_updates` + 注册命令菜单**。改过 `allowed_updates` 必须重访一次，否则新类型不推送。
## 使用方法

### 用户自助解封

1. 私聊发 `/unban` → 返回自助解封检查清单
2. 复制 `<code>` 里**整句**并发送 → 逐字整句匹配（多 / 少标点、夹带字符一律拒绝）
3. 解封全部配置群 → 成功回执 + 主群「联系管理员」按钮

在 D1 全局黑名单中的用户第一道闸就被拦（**永久封禁，只能 `/unban` 移除**）。

### 二次审核流程

两个按钮，复制内容交**真人管理员**使用：

- **📋 点击复制 GKY 添加白名单代码** —— 两行 `GKYbotSave\n用户ID`，粘贴到封禁记录对应的群发送
- **📋 点击复制 本地解封命令** —— `/unban 用户ID`，有权限的管理员发送（复制本身不改 D1）

复制按钮只进剪贴板，**机器人不会自动代发**（GKY 不认其它 Bot 代发的 `GKYbotSave`）。

## HTTP 接口

### 查询封禁记录（公开）

`GET /{TGID}` —— 查该 TGID 的 GKY 封禁记录（HTML），`?format=json` 返回结构化数据；公开可访问，不含敏感数据。

### 黑名单导出（受 TOKEN 保护）

`GET /{TOKEN}/export` —— 浏览器看 HTML 表格（带搜索），`?format=json` / `?format=csv` 下载（CSV 带 BOM，Excel 不乱码），`POST` 同路径返回 JSON；必须带正确 `TOKEN` 否则返回 405，字段全部 `escapeHtml` 转义。

### 黑名单清扫入口（受 TOKEN 保护）

`GET /{TOKEN}/purge` 分批清扫 D1 存量黑名单里仍在群里的人；`GET /{TOKEN}/purge/run` 立即执行一次（默认分批，避免撞子请求上限）。

## 常见问题

### 部署后却不生效：三个静默失效点

1. **Webhook 没初始化 = 一条消息都收不到。** 部署完必须访问 `/{TOKEN}`；改过 `allowed_updates` 必须重访一次（一旦显式声明，默认清单整体失效）。这一步不调不报错、日志也干净。确认：`/health` 里 webhook 状态应为 `set`。
2. **环境变量与源码默认值打架 = 你改的没生效。** 优先级是**环境变量 > 源码默认值**：后台已填同名变量时，改 `_worker.js` 顶部 `DEFAULT_*` 不生效，改源码要 `wrangler deploy`。反向地 `wrangler.toml` 必须 `keep_vars = true`，否则部署会用本地值覆盖远端变量（fork 后改过记得改回来）。
3. **D1 或 AI 没绑对 = 功能静默降级。** `binding` 必须正好是 `DB` / `AI`、`database_id` 要对得上：缺 D1 时自助解封失败关闭、各命令提示未绑定；缺 AI 时 `/adstats` 标注「未绑定，降级为评分 + 指纹两层」。

### 收不到、没反应

- **收不到群内手动封/解封的同步信号** → bot 必须是**群管理员**，然后重访初始化地址重订 webhook。
- **第一主人收不到详情 / 通知发不出** → 先私聊 bot 发一次 `/start` 建立会话，并核对 `OWNER_IDS[0]`；bot 不能主动给没聊过的人发私信。配置了 `OWNER_IDS` 也一样。
- **管理员命令没反应** → `/ban` `/spam` `/check` 鉴权是「**任一配置群**的管理员或群主」；`/blacklist` 只能私聊发；`/sban` 更严（限第一主人、副主人、该群群主，私聊仅前两者），其余人在群里**完全静默**。未授权者发隐藏指令群内静默、私聊才回「权限不足」，按钮点击时重新验权限。
- **群内发命令后还有 5 秒闪屏吗** → 不会，群内只发简洁汇总，完整明细私聊第一主人；群内发令者自己收不到详情，**私聊执行时自己收到**。
- **操作人标签** → `OWNER_IDS[0]` 标主人、其余标副主人，剩下按调用上下文兜底标管理员。

### 执行失败

- **`/ban` `/sban` `/spam` 报「Telegram 封禁失败 0/N」** → 群设置 → 管理员 → 本机器人，打开**封禁用户**（禁言与踢出都靠它）；`/sban` 撤回历史发言另需**删除消息**权限。
- **自助解封通过后仍不能发言** → 三种情况：`kicked` 要重新加群、被其它系统限言、在 GKY 全局黑名单（会触发二次审核提醒）。
- **发了正确确认句却没被解封** → 必须**完整逐字粘贴**整句，多/少标点、夹带字符一律拒；改过确认句要用当前生效那句。
- **批量超过 50 个** → 单次上限 50，超过拆批；预算不足的自动转批量任务（`/job` 查、`/jobrun` 补跑）。
- **黑名单用户的旧消息** → 踢出时自动撤回**最近 48 小时**（平台上限），更早的只能手动删；`/ban` 禁言不撤回，要清历史引用回复 `/spam`，或在群里对单个 TGID 发 `/ban` 顺带清扫当前群。
- **Windows 下 `git push` 报 socks5 代理错** → 不是本项目问题，把 git 代理改成 `http://127.0.0.1:端口`。

### 查询与外部依赖

- **`/banlist?tgid=...` 返回失败或无数据** → 依赖外部服务 `GKY_BANLIST_ENDPOINT`，外部不可用时等恢复或换后端（HTML 须与 `parseBanlistHTML` 兼容）。
- **`/admins` 显示「昵称:未获取 用户名:未获取」** → Bot API **只能查 bot 所在群的成员**，把 bot 拉进对方所在的群填 `PROFILE_LOOKUP_GROUPS`，或用 `STATIC_USER_PROFILES` 填静态资料。
- **想看 Telegram 返回的英文原文** → 回执只有中文原因，英文在 **Cloudflare 后台 → Workers → 本 Worker → 日志**。

### 广告检测

- **正常用户被误封** → `/pending` 拿序号 → `/ignore 序号`：一键解封 + 给命中指纹加误报，累计 3 次该指纹自动退役。
- **广告号没被检测到 / 同款查杀漏了号** → 引用回复 `/spam` 最快（自动学指纹，该文案进同款直封名单后直发即删 + 封）；手工加 `/addword`；被抢先删的用 `/recent` + `/learnlast`。
- **`/adstats` 显示「降级为评分 + 指纹两层」** → Workers AI 没绑上，`wrangler.toml` 加 `[ai]` 段，绑定名必须**正好是** `AI`。
- **广告检测的 13 张表建失败** → **既有功能完全不受影响**，广告层静默跳过并进 60 秒冷却，用 `/adstats` 诊断。
- **处置完广告，正文又被某个 bot 带引用贴回群里** → 已拆两条通道：**bot 发的广告 → 删 + 封**；**已处置正文的重发 → 只删不封**。
- **管理员置顶后被 bot 删除并取消置顶** → 两种成因：服务消息被清扫缓存误删（v2 已修复，旧版升级清一次存量缓存）；频道转发帖本身被广告检测删掉（另一条路径）。
